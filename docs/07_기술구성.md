## 폴더 구조 (요약 — 자세한 코드 지도는 [11_코드구조.md](11_코드구조.md))

survivor/

├─ scenes/              타이틀 · 생존자 고르기 · 게임 · 결과 · (은신처)

│  └─ tools/            자동 플레이, 화면 캡처, 통계
├─ data/                생존자·무기·장비·진화·좀비·이벤트·감염도 표 (JSON) — 03 문서의 숫자
├─ art/                 픽셀 그림 (생존자·좀비·타일·아이콘) + 그림 만드는 스크립트

├─ fonts/               Pretendard, Galmuri + 사용 조건
└─ docs/                이 문서들

- **숫자는 data/ 표에만** 둔다 → 밸런스는 표만 고치면 됨.
- 좀비 300마리 성능: 물리 엔진 대신 거리 계산 + 칸 나누기(가까운 것끼리만 계산), 총알·좀비·조각은 미리 만들어 두고 재사용(풀링), 그리기는 한 번에 몰아서.

## 저장 (2026-11-07 묶음 3)
- 고철·은신처 단계·해금·업적·도감·기록·설정·오늘의 도전·누적 숫자를 `user://save.json` 한 파일에 (`scripts/autoload/save_data.gd`). 웹판에서는 user:// 가 브라우저 저장소(IndexedDB)라 같은 브라우저면 남는다.
- 저장하는 때: 판 끝(정산 뒤) · 은신처 강화 · 설정 바꿀 때 · 판 시작(마지막 감염도) · 앱을 닫거나 다른 앱으로 갈 때.
- 저장 손실 막기(문서 12 §6): 임시 파일(`save.json.tmp`)에 다 쓴 뒤 이름을 바꾸고, 앞 파일은 `save.backup.json` 으로 남긴다. 켤 때 본 파일 → 임시 → 예비 순서로 읽고, 다 깨졌으면 처음 값으로 시작(멈추지 않음). 칸마다 타입이 다르면 그 칸만 처음 값.
- 시험 봇(`--autoplay`)은 저장 파일을 건드리지 않는다. 저장까지 시험하려면 `--save=tools/out/…/save.json`.

### 자동 로드 `SaveData` 를 더한 이유 (project.godot `[autoload]`)
- 저장은 게임 전체에서 하나만 있어야 하는 것(문서 10 §7)이라 자동 로드로 둔다. 순서는 GameData → **SaveData** → SceneRouter → SoundPlayer: SceneRouter 가 켤 때 저장된 '마지막 감염도'를 읽고, SaveData 는 처음 설정 값을 GameData 표에서 읽기 때문. 소리 크기는 SoundPlayer 가 준비된 뒤 한 박자 늦게 넣는다.

## 시험 방법
- **자동 플레이 모드**: 실행할 때 `-- --autoplay --speed=4 --shots=폴더` → 알아서 피하고 강화 고르며 진행, 정해진 시점마다 화면 캡처
- 스크립트 오류 확인: 실행 기록에 오류(ERROR / SCRIPT ERROR)가 없는지
- 사람 시험: PC 창(폰 크기)에서 마우스로, 그다음 실제 폰(웹 링크)

| 빼는 파일 | `tools/out/*` | 시험 결과·캡처 |
| head 에 넣는 것 | `sound_unlock.js`(맨 앞), 설명·링크 미리보기(og:title·description·image), 바탕색 | 폰 소리 / 카톡 등에 링크를 보내면 제목·그림이 뜨게 |
