# 10. 코드 규칙 — 사람이 읽을 수 있는 코드 (확정 2026-11-07)

> 원칙: **처음 보는 사람이 파일 하나를 열었을 때, 위에서부터 읽으면 무슨 일을 하는지 알 수 있어야 한다.**
> 짧게 쓰는 것보다 알아보기 쉽게 쓰는 게 먼저다.
> 적용 대상: 게임 코드 전부 (`scripts/`, `data/`, `tools/`). 단, `docs/style_preview/` 의 시안 페이지는 버리는 시험물이라 예외.

---

## 1. 이름
| 대상 | 규칙 | 좋은 예 | 나쁜 예 |
|---|---|---|---|
| 변수·함수 | 영어 단어를 **줄이지 않고** snake_case | `zombie_count`, `spawn_zombie()` | `zc`, `spwnZ()`, `s`, `z` |
| 함수 | **동사로 시작**, 하는 일이 이름에 보이게 | `apply_damage()`, `find_nearest_zombie()` | `do()`, `handle()`, `process2()` |
| 참·거짓 | `is_` · `has_` · `can_` 로 시작 | `is_in_light`, `can_use_skill` | `light`, `flag` |
| 상수 | 대문자 UPPER_SNAKE | `MAX_ZOMBIES`, `RUN_SECONDS` | `maxz` |
| 클래스·장면·노드 | PascalCase | `Survivor`, `ZombieSpawner` | `obj1`, `Node2D2` |
| 신호(signal) | 이미 일어난 일 (과거형) | `died`, `leveled_up`, `skill_used` | `die`, `on_level` |
| 파일 | 안에 든 것 이름 그대로 snake_case | `zombie_spawner.gd` | `util.gd`, `stuff.gd`, `new.gd` |
- 한 글자 이름은 `for i in range(n)` 같은 아주 짧은 반복의 번호만 허용한다.
- 같은 것은 어디서나 같은 이름: 문서의 "백신 조각" = 코드의 `vaccine_shard` (아래 §8 용어표).

## 2. 크기
- **파일 하나 = 한 가지 일.** 300줄이 넘으면 나눌 수 있는지 본다.
- **함수 하나 = 한 가지 일.** 40줄이 넘으면 나눈다.
- 들여쓰기가 4단계를 넘으면 함수로 빼낸다.
- 한 줄에 문장 하나. 삼항(`a if b else c`)을 겹쳐 쓰지 않는다.

- 프로젝트 설정에서 **타입 없는 선언을 경고**로 켠다 (`debug/gdscript/warnings/untyped_declaration = 경고`). 새 코드는 **경고 0개**.

## 4. 숫자는 데이터 표에
- 밸런스 숫자(체력·속도·피해·시간)는 **`data/*.json` 에만** 둔다. 코드에 `55`, `0.6` 같은 숫자를 바로 쓰지 않는다.
- 데이터가 아닌 고정값은 이름 붙인 상수로: `const SCREEN_WIDTH := 180`.
- 데이터 키 이름도 §1 규칙을 따른다: `"move_speed": 55`, `"skill_cooldown_seconds": 18`.

## 5. 파일 머리말 (모든 파일 필수)
**모든 파일 맨 위에** 어떤 파일이고 무엇을 하는지 적는다. 예외 없음 — 머리말 없는 파일은 완성이 아니다.

### 들어갈 내용 (4줄)
| 칸 | 내용 |
|---|---|
| 파일 | 프로젝트 안 경로 |
| 하는 일 | 이 파일이 맡은 일 1~2문장 (쉬운 말) |
| 쓰는 곳 | 누가 이 파일을 쓰는지 / 이 파일이 무엇을 쓰는지 |
| 근거 문서 | 관련 기획 문서 위치 (없으면 "없음") |

### 파일 종류별 쓰는 법
| 종류 | 쓰는 법 |
|---|---|
| GDScript `.gd` | 맨 위 `##` 주석 4줄 (Godot 편집기 설명에도 보임) |
| 장면 `.tscn` | 맨 위 노드의 `editor_description` 에 4줄 (Godot 이 저장할 때 일반 주석은 지워서) |
| 데이터 `.json` | 맨 앞 키 `"_설명"` 에 4칸. 불러오는 코드는 `_` 로 시작하는 키를 건너뜀 |
| 셰이더 `.gdshader` | 맨 위 `//` 주석 4줄 |
| 파이썬·도구 `.py` | 맨 위 `"""` 설명 4줄 |
| HTML | 맨 위 `<!-- -->` 4줄 |
| 문서 `.md` | 제목 바로 아래 한 줄 설명 |
| 그림·소리·글꼴 (주석 못 넣음) | **폴더마다 `README.md`** 에 파일별 한 줄 설명 + 출처·사용 조건 |
| `project.godot` | Godot 이 저장할 때 주석을 지움 → 설정 설명은 문서 07 에 적는다 |

### 예시
```gdscript
## [파일] scripts/game/zombie_spawner.gd
## [하는 일] 화면 밖에서 좀비를 만들어 낸다. 시간이 지날수록 나오는 속도와 종류를 바꾼다.
## [쓰는 곳] game.gd 가 한 판 시작할 때 만든다 / data/spawn_curve.json, data/zombies.json 을 읽는다.
## [근거 문서] 03 §6 좀비 (늘어나는 정도)
class_name ZombieSpawner
extends Node
```
```json
{
  "_설명": {
    "파일": "data/weapons.json",
    "하는 일": "무기 12종의 단계별 숫자 (피해, 공격 간격, 사거리 …)",
    "쓰는 곳": "scripts/game/weapon_*.gd 가 읽는다",
    "근거 문서": "03 §2 무기"
  },
  "pistol": { "damage": 10, "attack_interval_seconds": 0.6 }
}
```

## 5-2. 주석
- **한국어**로 쓴다.
- 코드가 **"무엇"**을 하는지는 이름으로 보여 주고, 주석에는 **"왜"**를 쓴다.
  ```gdscript
  # 좋은 예: 왜 그런지
  # 화면에 300마리가 넘으면 폰이 느려져서, 먼 좀비를 가까이 옮겨 재사용한다.
  # 나쁜 예: 코드를 그대로 읽은 것
  # i 를 1 늘린다
  ```
- 규칙의 근거가 문서에 있으면 문서 위치를 적는다: `# 빛 안 좀비는 느려짐 (문서 02 §4, 03 §7)`
- 주석으로 막아 둔 옛 코드는 남기지 않는다 (git에 기록이 있다). 쓰지 않는 코드도 지운다.

## 6. 파일 안 순서 (Godot 공식 스타일)
1. 파일 설명 주석 · `class_name` · `extends`
2. `signal`
3. `enum`
4. `const`
5. `@export` 변수
6. 일반 변수
7. `@onready` 변수
8. `_ready()` · `_process()` 같은 엔진 함수
9. 다른 파일에서 부르는 함수
10. 이 파일 안에서만 쓰는 함수 (이름 앞에 `_`)

- 들여쓰기는 탭, 함수 사이는 빈 줄 두 줄.

## 7. 연결 방식
- 다른 노드를 깊숙이 찾아가지 않는다: `get_node("../../UI/Hud")` ✗ → **신호(signal)로 알리거나**, 위에서 넘겨준다.
- 게임 전체에서 하나만 있는 것(저장, 데이터 불러오기)만 자동 로드(Autoload)로 둔다.
- 데이터 파일을 못 읽으면 **어느 파일의 어느 키인지** 오류 메시지로 분명히 남긴다 (`push_error("data/weapons.json: 'pistol' 에 damage 가 없음")`).

## 9. 확인
- 새 코드를 넣을 때마다: **머리말 검사** → **코드 지도 갱신** → Godot 경고 0개 → 자동 플레이 시험 통과 → 화면 캡처 확인.
- 머리말 검사는 `tools/check_headers.py` (v0.1 에서 만듦): 모든 파일·폴더를 훑어 머리말 4칸이 없는 파일, `README.md` 없는 그림·소리 폴더, **[11_코드구조.md](11_코드구조.md) 에 없는 코드 파일**을 찾아 알려 준다.

## 10. 코드 지도 (전체 구조 문서)
- 전체 구조는 **[11_코드구조.md](11_코드구조.md)** 한 곳에 적는다: 폴더 지도, 화면 흐름, 장면 구성, 한 프레임 순서, 신호 표, 데이터 표, 자주 하는 일.
- 파일을 **만들거나 옮기거나 지우면 같은 작업 안에서** 11 문서도 고친다. 지도와 실제가 다르면 완성이 아니다.
- 단계가 끝날 때 코드 검토(가독성 포함)를 한 번 돌린다.
- git 커밋 메시지는 한국어로 **무엇을, 왜** 바꿨는지.
